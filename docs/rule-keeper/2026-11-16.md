# Rule keeper run 2026-11-16

Scope: the last 30 merged PRs (#688 back to #633) with their reviews and comments, the agent workflows in
`.github/workflows/`, and `tools/check/`. No PR was open with `needs-human` at run time.
Run logs were not readable: every run count below is `open`.

Template-managed files (`AGENTS.md`, `.agents/roles/`, `tools/`, `.github/workflows/`, `Makefile`, `tests/agent/`) are
not edited by this run. Each finding names the file to change in the template.

## Contradictions and gaps in rules

1. **PR body cap is not enforced.** `AGENTS.md` (Commits and PRs) says the body is at most 5 lines and "Enforced by CI".
   `tools/check/check_pr_form.py` only checks that the body is not empty (no line count, no test).
   Proposed: count body lines in `check_pr_form.py`, without the optional `## Friction` section. Runs per week: open.
2. **Guard title list is stale in the role.** `.agents/roles/orchestrator.md` lists four guard title prefixes.
   `tools/trusted_issues.py` (`GUARD_TITLES`) also trusts `Canary: `. Proposed: add the prefix, or point the role at
   `tools/trusted_issues.py` only.
3. **Missing rule: slip format.** Three of the 30 PRs changed how a slip is read (#655 `Files:` in a one-line prose slip,
   #659 unblocker `Slip for #` prefix that never matched, #662 `step_landed`). No role states that a slip has a
   `Files:` line of its own; only `tools/slip.py` defines it. Proposed: one sentence in `orchestrator.md` and `developer.md`.

## Recurring work steps that a script should do

4. **Parking with Daniel is split between script and model.** `orchestrator.yml` step 1c tells the model to add the
   `needs-human` label and run `gh pr edit <n> --add-reviewer Bankaifan` by hand, then post the note. Line 243 of the
   same prompt says the note goes through `tools/agent_guard.py park`, which only posts the note with its marker
   (`park()`, `post_owner_note()`). Proposed: `park` also adds `needs-human` (via `ensure_label` and `add_labels`) and
   the review request, so the model only writes the German text. Runs per week: open.
5. **Label creation before every label use.** The orchestrator prompt runs `gh label create <label> --force` before
   adding any label (`orchestrator.yml`, around line 215). The label set is fixed (`needs-human`, `review:N`,
   `agent:dev`, `prio:N`, `risk:*`, `model:sonnet`, `unblock:1`, `restart:1`). Proposed: one script step before the
   model step that ensures these labels exist. Runs per week: open.
6. **Scout options check.** `.agents/roles/scout.md` requires exactly one `Recommended:` line for an idea with options,
   and the `Zusammenfassung für Daniel:` heading. No script checks either (no reference in `tools/`). Proposed:
   a check in `tools/` run after the scout step. Runs per week: open.

## Considered and not changed

- **Canary append is a model step on purpose.** `tools/canary.py` opens a fixed-slip issue (append one line to
  `docs/canary.md`, haiku). Four of the 30 merged PRs (#657, #666, #686, #688) are these appends. Scripting the
  append would remove the pipeline test the canary exists for, so the step stays.
- **Security-review verdicts, body-hash lines and release PRs** are already written by scripts. No model step to replace.
- **Rules that never mattered:** no rule could be shown unused from the 30 PRs. Nothing proposed for removal.
